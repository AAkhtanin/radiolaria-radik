# Finite informational tasks

The normal application accepts three profiles: compare approved document
conditions, explain conditions and exceptions, and verify a supplied answer
against approved sources. `app/task_spec.py` holds the immutable task contract.
An ambiguous natural-language request remains in `CLARIFICATION_REQUIRED`; it
does not reserve a model attempt. Verification requires the supplied candidate.

Each task selects one to four logical source IDs within an explicit resource
scope. Intake reopens the owned UTF-8 bytes and records the observed revision and
SHA256. A changed revision invalidates reuse. After the first dispatch, a task
cannot silently replace its semantic origin or source dependencies. Changed
intent, criterion, candidate or source versions require a separate task with a
historical predecessor link. That link restores no permission.

`app/task_store.py` retains task selection, the sequential queue, append-only
history and immutable accepted-result files. Switching A to B and back to A does
not discard either result. Restart converts an unfinished local task into an
interrupted material state; it does not retry a request or restore live native
authority. Cancellation prevents future dispatch and retains history. The menu
does not claim that a remote operation was cancelled without a receipt.

Every started round, including a zero-provider memory or U2 round and an
interrupted or failed round, remains in lifetime history. The historical task
policy's three-start limit and v01/v02 recovery allowances retain their original
meanings. A versioned normal operation uses a separate finite command profile,
with no lifetime task quota. Every explicit `run` creates a unique durable grant
bound to the current task/spec/dependencies, operation, source/admission,
policy/settings and history ordinal before TaskStore commit and reservation.
Cold permits at most3 role reservations; memory-only and native continuation
permit0. Closure, failure and restart cannot reuse an old scope or consumed
recovery action. UNKNOWN retains occupancy. Budget, ledger and task history
validate the same binding; memory miss has no cold fallback. The preserving
v05 transition changes no actual state during source preparation. The existing
model ledger remains the sole model-attempt counter; native U2 limits do not change.

`app/dynamic_roles.py` issues typed live O/A/C requests. Each request binds the
current task, approved raw-source identities, exact UTF-8 byte spans, closed
effect policy and explicit model settings. Transport-emitted immutable receipts
establish O then A. The native source family and BSEP exist before Architect.
Critic receives the actual validated native Work projection after execution,
including the exact candidate and actual Work hash. It does not review a guessed
or producer-declared execution result. Native execution stays in
`app/dynamic_native.py`; this request chain does not implement a second native
orchestrator or a provider inside pure Work.

Dynamic memory uses the existing `DocumentMemory` discovery, typed eligibility,
fresh Root descent and actual payload-readback engine under a separate finite
schema and policy. Its meaning key binds the normalized profile, goal, topic,
criterion, supplied candidate and current source IDs, revisions and hashes.
Task identity, selection order and restart time are separate. A new task ID does
not itself prevent reuse, and similar wording does not itself permit reuse.
The consumer must execute a current typed operation after descent. Historical
record clocks, acceptance times and validity endpoints are never renewed by
loading the material. The legacy two-document schema and its recorded bytes
remain available under their original policy.

The console offers task creation, queue, select, clarification, run,
same-process bounded continuation, cancellation, result, memory, status and
explicit model/effort settings. `compare` is a compatibility intake into the new
task path. Model settings change only between completed rounds; global counts
and historical rows are retained. A restarted task must first undergo fresh
source and memory checks before same-process continuation can use its result.

Each runtime task supplies a current policy reader. It reopens the existing
owned closed effect-policy bytes and requires `save_allowed=False`; their raw
SHA256, revision and owned workspace bind the informational policy projection.
Its finite decision window is anchored once at controller construction. This
does not edit the original policy, extend an old SAVE consent, or renew a memory
clock. Every subsequent role reservation and native dispatch rereads that
projection and the task's persisted cancellation/scope state. A changed policy,
cancelled task or changed original source dependency closes the current path.

An accepted native result is persisted before memory writeback. If a later
writeback or reporting step fails, the task index retains that accepted material
as `FAILED_AFTER_ACCEPTANCE` with the late failure recorded separately. This
state does not claim a completed memory lifecycle or schedule an automatic
retry. The original checkpoint remains discoverable as `result legacy` and in
task/status summaries; it is historical material under its original clocks.

Informational source-update continuation is blocked because no current
Root-bound NO_EFFECTS source-context carrier has been admitted for G2E. That
carrier is separate from a PURE capability invocation's absent action packet;
the latter is not a proof of informational G2E compatibility or impossibility.
The profile does not reuse an old SAVE grant or invent a consequential packet.
The `update` command reports this boundary and offers a separate task intake. It does not
replace affected-only native continuation with an undisclosed whole-task run.
SAVE remains unavailable. Source preparation or an offline fixture establishes
no new owner AUTH, actual model observation, action permission or live result.
