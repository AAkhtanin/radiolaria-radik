# Proposed informational source authority for native G2-E

Status: upstream contract proposal only. This passage changes no reference
source, registered transition, ABI, executor, policy or native budget. The
informational selective-delta case is blocked and unaccepted.

The missing contract is a public, current, Root-authorized **source-context
carrier for an informational dependency set**. It must be constructible and
validatable with no action permission and no consequential capability. This is
separate from the packet identity of a capability invocation. A PURE
`BoundCapabilityInvocation` correctly keeps `candidate_id=None` and
`packet_id=None`; an independent legitimate source carrier would not alter it.

The current `ContinuousDeltaSourceContextV01.g2a_packet` is mandatory at
`continuous_delta_runtime_v01._source_context_reason_v01`. The predicate
requires common Root-bound action-packet validation, mandatory dependency local
Root acceptance, matching packet dependency candidate, matching current
observations and packet-bound invalidation evidence. Its public native packet
builder and validator in `action_commit_packet_v02` require a genuine
`MOCK_CONSEQUENTIAL` admission and canonical applicable permission. Current
Root action authorization also checks that permission is required, present and
in scope. There is no public alternative carrier contract for NO_EFFECTS.

The old owned `prepare_pending → document_delta_arguments` adapter supplied a
real pending SAVE after the current controller verified `save_allowed`. That
success proves the permitted-action path. A consumed CLOSED quota, old packet,
fake pending SAVE or conversion of PURE to consequential cannot establish a
current informational carrier.

The smallest semantic extension is a versioned informational authority
alternative in E's source-context contract, with its own public constructor and
validator. Its obligations would be:

- Bind the exact current task, owning Root, transaction, approved logical
  sources, source revision/hash observations, initial Work origin, semantic
  proposal and BSEP accepted through the current public informational path.
- Carry a fresh local Root decision about using that exact dependency set for
  information only, with a bounded temporal envelope and current policy
  identity. It must convey no action permission, effect budget or executor
  authority.
- Bind the dependency candidate and invalidation evidence by identity so a
  changed observation cannot be paired with a foreign or historical origin.
- Let E's source validation accept exactly one authority alternative: the
  existing permitted action carrier or the new informational carrier. Reject
  ambiguous, mixed, stale, missing or cross-task authority. Keep PURE invocation
  identity rules unchanged.
- Keep Pair1 minimal affected-set review, exact recomputation outputs, retained
  typed sibling consumption, Pair2 PreservationProof and zero provider-call
  checks mandatory. The extension supplies missing source authority; it does
  not authorize a whole-fractal fallback or remove preservation checks.

A future upstream change would therefore need a versioned carrier definition,
its public builder/validator and a corresponding E source-validation branch,
plus contract/schema and public-entry conformance evidence. Its exact reference
API and ABI design belongs to the upstream owner. Radik must not implement a
lookalike object or an adapter bypass while that public contract is absent.
